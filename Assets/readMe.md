## 구현 원칙
구현할 때는에는 꼭 아래의 원칙을 지켜야 한다.
- YAGNI (You Aren't Gonna Need It) 원칙을 중요하게 지킨다. 나중에 필요할 것이라고 '미리 짐작'해서 코드를 작성하지 않는다.
- KISS (Keep It Simple, Stupid) 원칙을 중요하게 지킨다. 코드를 작성할 때 불필요하게 장황하고 복잡하게 만드는 것을 경계한다.
- Rule of Three + AHA (Avoid Hasty Abstractions) — 3번 반복 전까지 추상화를 서두르지 말라.
- Layered Architecture + Dependency Inversion Principle (DIP) — 레이어를 분리하고 구체가 아닌 추상에 의존하라.
- Single Responsibility Principle (SRP) + Information Hiding (Parnas) — 변경 이유가 같은 것끼리만 묶어라.
- Intention-Revealing Names (Clean Code) + Self-Documenting Code — 코드 자체가 의도를 드러내게 하라.

# 게임 스토리

평범한 수업 시간이던 어느 날.

누군가는 코드를 짜고 있다.

# 미구현 기능 상세 기획

## 문서 목적

현재 구현된 플레이어 이동, 맵 로딩, 폭발물, 대화 UI, 인게임 UI의 프로토타입을 하나의 완주 가능한 게임으로 연결하기 위한 MVP 기준을 정의한다.

이 문서에 없는 상점, 저장과 불러오기, 체력, 장비, 멀티플레이 기능은 핵심 플레이가 완성되기 전까지 구현하지 않는다.

---

## MVP 확정 기준

- 전체 진행은 9개 스테이지로 구성한다.
- 헬스장은 별도 번호를 갖지 않고 `붕괴된 복도` 내부의 짧은 이동 구간으로 포함한다.
- 모든 사망 요소는 체력 감소 없이 즉사로 통일한다.
- 제한 시간의 초기값은 8분으로 두되 플레이 테스트 후 조정할 수 있게 한다.
- 구조 대상은 기숙사에 있는 학생 4명으로 고정한다.
- 학생을 한 명도 구조하지 않아도 운동장 도착 시 클리어할 수 있지만 낮은 등급을 받는다.
- 사망 또는 시간 초과 후 재시작하면 교실부터 전체 게임을 다시 시작한다.
- 대화 중에도 제한 시간은 흐르며 플레이어 이동만 잠시 차단한다.
- 상점 시스템은 의미와 보상 구조가 확정될 때까지 구현 대상에서 제외한다.

---

## 최종 스테이지 순서

```text
1. 교실
2. 학교 복도
3. 학교 계단
4. 교무실
5. 붕괴된 복도 + 헬스장 통로
6. 기숙사
7. 기숙사 계단
8. 기숙사 1층
9. 운동장
```

스테이지는 별도 Unity Scene으로 나누지 않는다. 하나의 GameplayScene 안에서 현재 스테이지 프리팹만 교체한다. 플레이어, 카메라, 제한 시간, 구조 학생, 카드키 상태, HUD는 스테이지 전환 중에도 유지한다.

---

## 게임 진행 상태

게임 전체 상태는 다음 정보만 유지한다.

| 상태 | 설명 |
| --- | --- |
| 남은 시간 | 기본 8분에서 시작하며 0이 되면 시간 초과로 사망 |
| 현재 스테이지 | 현재 로드된 스테이지와 입장 위치 |
| 구조 인원 | 구조를 시작한 학생 수, 최대 4명 |
| 카드키 | 교무실에서 획득했는지 여부 |
| 게임 상태 | 진행 중, 게임 오버, 클리어 |

게임 오버나 클리어가 확정되면 플레이어 입력과 제한 시간 갱신을 중지한다.

### 완료 조건

- 스테이지가 바뀌어도 남은 시간, 구조 인원, 카드키가 유지된다.
- 재시작하면 모든 진행 상태가 초기값으로 돌아간다.
- 게임 오버와 클리어가 중복 실행되지 않는다.

---

## 플레이어 조작 및 상호작용

### 이동

- 이동은 Input System의 Move 액션 하나만 사용한다.
- 대각선 이동 속도는 정규화해 수평 이동보다 빨라지지 않게 한다.
- 이동 방향에 따라 캐릭터 좌우 이미지를 전환한다.

### 상호작용

- F키를 누르면 현재 범위 안의 상호작용 대상 하나와 상호작용한다.
- 상호작용 대상이 없을 때 F키를 눌러도 오류가 발생하지 않는다.
- 학생, 카드키, 조사 가능한 오브젝트가 같은 상호작용 규칙을 사용한다.
- 상호작용 가능한 대상 근처에서는 간단한 키 안내를 표시한다.

### 완료 조건

- 이동 입력과 상호작용 입력이 서로 다른 코드 책임으로 분리된다.
- 대화 중에는 이동 입력이 적용되지 않는다.
- 대상이 파괴되거나 범위를 벗어나면 상호작용 대상이 즉시 해제된다.

---

## 제한 시간 및 게임 오버

- 교실 스테이지 로딩이 끝난 순간부터 카운트다운을 시작한다.
- HUD에는 `분:초` 형식으로 남은 시간을 표시한다.
- 10초 이하가 되면 시간 표시를 붉은색으로 변경한다.
- 시간이 0이 되면 사망 원인을 `건물 붕괴`로 표시한다.
- 화재, 폭발, 낙하물 등 다른 위험 요소에 닿으면 해당 사망 원인을 표시한다.
- 게임 오버 화면에서는 재시작과 타이틀 복귀만 제공한다.

### 완료 조건

- 게임 오버 화면이 열린 뒤 시간이 음수로 계속 감소하지 않는다.
- 재시작 버튼이 GameplayScene을 정상적으로 다시 시작한다.
- 타이틀 버튼이 TitleScene으로 이동한다.

---

## 구조 및 학생 추종

학생은 다음 네 상태를 가진다.

```text
대기 -> 대화 -> 추종 -> 운동장 구조 완료
```

- 학생과 처음 상호작용하면 학생별 코믹 대화를 시작한다.
- 마지막 대사가 끝나면 구조 인원을 1명 증가시키고 플레이어 추종을 시작한다.
- 이미 구조한 학생과 다시 상호작용해도 구조 인원이 중복 증가하지 않는다.
- 여러 학생이 구조되면 플레이어 뒤에서 한 줄로 따라간다.
- 학생이 너무 멀어지면 앞 추종 대상 근처로 위치를 보정한다.
- 추종 학생은 스테이지 프리팹의 자식으로 두지 않아 맵 전환 시 파괴되지 않게 한다.
- 운동장에 도착하면 추종을 멈추고 안전 구역으로 이동한다.

### 학생별 연출

| 학생 | 구조 전 행동 | 구조 시작 조건 |
| --- | --- | --- |
| 샤워 중인 학생 | 샤워를 계속하려 함 | 대화 종료 |
| 자는 학생 | 잠에서 깨지 않음 | 반복 상호작용 후 대화 종료 |
| 컵라면 학생 | 다 먹고 가겠다고 함 | 짧은 대기 연출 후 대화 종료 |
| 개발 중인 학생 | 저장 중이라고 함 | 저장 완료 연출 후 대화 종료 |

학생별 행동은 대사와 짧은 대기 시간만 다르게 하고 별도의 복잡한 AI는 만들지 않는다.

### 완료 조건

- 네 학생을 각각 한 번만 구조할 수 있다.
- 네 학생이 연속된 스테이지 전환을 통과해 운동장까지 따라온다.
- 학생 충돌이 플레이어 이동이나 문 통과를 막지 않는다.

---

## 카드키와 잠긴 출구

- 교무실에는 기숙사 출입 카드키 하나가 배치된다.
- 카드키를 획득하면 HUD에 카드키 아이콘을 표시한다.
- 기숙사로 향하는 출구는 카드키가 없으면 작동하지 않는다.
- 잠긴 출구와 접촉하면 `카드키가 필요하다`는 안내를 표시한다.
- 카드키가 있으면 별도의 소비 없이 출구를 통과한다.
- 스테이지를 다시 로드해도 카드키 상태는 유지한다.

### 완료 조건

- 카드키 없이 기숙사 스테이지로 이동할 수 없다.
- 카드키 획득 후 같은 출구가 정상적으로 열린다.

---

## 공통 위험 요소

모든 위험 요소는 접촉 시 사망 원인만 다르고 동일한 즉사 규칙을 사용한다.

| 위험 요소 | 사망 문구 |
| --- | --- |
| 화재 | 화재에 휩싸였습니다. |
| 폭발 | 폭발에 휘말렸습니다. |
| 낙하물 | 낙하물에 맞았습니다. |
| 유리 파편 | 유리 파편에 맞았습니다. |
| 추락 | 아래로 추락했습니다. |
| 붕괴 잔해 | 붕괴 잔해에 깔렸습니다. |
| 침수 | 물에 휩쓸렸습니다. |
| 시간 초과 | 건물이 붕괴했습니다. |

폭탄 코드는 폭발 예고와 이펙트만 담당한다. 실제 사망 판정은 폭발 영역의 공통 위험 요소가 처리한다.

### 완료 조건

- 각 위험 요소가 정확한 사망 문구를 전달한다.
- 게임 오버가 한 번만 호출된다.
- 비활성화된 위험 요소는 플레이어를 사망시키지 않는다.

---

## 스테이지별 미구현 기믹

### 1. 교실

- 정적인 불길 미로를 먼저 완성한다.
- 이동 가능한 경로가 하나 이상 존재해야 한다.
- 플레이 시간이 너무 길어질 경우 입구 쪽부터 불길이 단계적으로 확산된다.
- 불길 확산은 플레이 테스트 후 필요할 때만 구현한다.

### 2. 학교 복도

- 반대 방향으로 움직이는 학생은 정해진 직선 경로를 왕복한다.
- 자습 감독 교사와 충돌하면 즉사한다.
- 낙하물은 바닥 경고 표시 후 떨어져야 한다.

### 3. 학교 계단

- 폭발 전에 시각 또는 음향 경고를 제공한다.
- 폭발 후 일부 발판을 비활성화하고 추락 영역을 활성화한다.
- 안전한 이동 타이밍이 최소 한 번은 보장되어야 한다.

### 4. 교무실

- 화면 또는 맵 위에 연기 오버레이를 표시해 시야를 제한한다.
- 화재는 희미한 붉은빛으로 위치를 추측할 수 있게 한다.
- 카드키를 획득해야 다음 주요 출구를 사용할 수 있다.

### 5. 붕괴된 복도와 헬스장

- 잔해는 이동 불가능한 벽 역할을 한다.
- 유리 파편과 추가 낙하물은 즉사 위험 요소로 처리한다.
- 헬스장 덤벨은 경로를 막거나 이동을 방해하지만 별도 시스템은 만들지 않는다.

### 6. 기숙사

- 네 종류 학생의 대화와 구조를 모두 배치한다.
- 구조하지 않은 학생은 해당 위치에 남는다.
- 출구를 통과할 때 구조 학생이 모두 함께 다음 스테이지로 이동한다.

### 7. 기숙사 계단

- 중앙 물 구역에서는 관성이 강해져 방향 전환이 느려진다.
- 난간 근처는 정상 이동이 가능한 안전 경로다.
- 중앙에서 일정 시간 이상 멈추면 침수로 사망한다.

### 8. 기숙사 1층

- 초기에는 화재가 출구를 막는다.
- 지정 위치 진입 시 천장 폭발과 물 낙하 연출을 실행한다.
- 이벤트 이후 화재를 비활성화하고 물 타일을 활성화한다.
- 물 타일에서는 이동 관성이 증가한다.

### 9. 운동장

- 운동장 진입 시 제한 시간을 멈춘다.
- 추종 학생을 안전 구역으로 이동시킨다.
- 구조 인원과 남은 시간을 기준으로 등급을 계산한다.
- 결과 화면에서 타이틀 복귀와 다시 시작을 제공한다.

## 클리어 등급

| 등급 | 조건 |
| --- | --- |
| S | 학생 4명 구조, 남은 시간 2분 이상 |
| A | 학생 4명 구조, 남은 시간 2분 미만 |
| B | 학생 2~3명 구조 |
| C | 학생 0~1명 구조 |

등급 계산에는 추가 점수나 아이템 보너스를 넣지 않는다. 플레이 테스트 후 구조 인원 외의 평가가 필요할 때만 확장한다.

## 필수 UI

- TitleScene: 시작, 종료
- HUD: 남은 시간, 구조 인원 `현재/4`, 카드키 보유 여부
- 상호작용 안내: 상호작용 가능한 대상 근처에서만 표시
- 대화 패널: 학생 이름과 현재 대사
- 게임 오버: 사망 원인, 재시작, 타이틀 복귀
- 결과 화면: 구조 인원, 남은 시간, 클리어 등급, 다시 시작, 타이틀 복귀

UI는 시간이나 구조 상태를 직접 계산하지 않고 게임 진행 상태의 값을 표시만 한다.

## 구현 순서

### 0단계: 프로젝트 복구

- 누락된 URP와 Renderer2D 설정 복구
- 플레이어 입력 스크립트 파일명과 씬 참조 수정
- 손상된 맵 데이터와 누락 스크립트 제거
- Build Settings에 TitleScene과 GameplayScene 등록

### 1단계: 완주 가능한 수직 구간

- 교실, 학교 복도, 임시 운동장 세 구간 연결
- 플레이어 이동, 스테이지 전환, 제한 시간 구현
- 공통 위험 요소, 게임 오버, 재시작 구현
- 임시 결과 화면까지 도달 가능하게 구현

### 2단계: 핵심 목표

- 학생 한 명의 대화, 구조, 추종 구현
- 카드키 획득과 잠긴 출구 구현
- 구조 인원과 카드키 HUD 연결
- 학생 네 명으로 확장

### 3단계: 전체 스테이지

- 학교 계단, 교무실, 붕괴 복도, 기숙사 계단, 기숙사 1층 추가
- 각 스테이지 기믹과 사망 원인 연결
- 운동장 결과와 등급 계산 완성

### 4단계: 정리와 플레이 테스트

- Test 스크립트와 사용하지 않는 테스트 씬 제거
- 중복 이미지와 TextMesh Pro 예제 리소스 정리
- 제한 시간, 이동 속도, 기믹 경고 시간을 플레이 테스트로 조정
- 시작부터 엔딩까지 누락 참조와 예외 없이 플레이되는지 확인

## 전체 완료 기준

- TitleScene에서 시작해 운동장 결과 화면까지 한 번의 플레이 흐름으로 진행할 수 있다.
- 제한 시간, 사망, 재시작이 모든 스테이지에서 동일하게 동작한다.
- 네 학생을 구조하고 스테이지 전환 후에도 운동장까지 데려갈 수 있다.
- 카드키 획득 전후로 잠긴 출구 동작이 달라진다.
- 모든 사망 요소가 올바른 사망 원인을 표시한다.
- 결과 화면이 구조 인원과 남은 시간에 맞는 등급을 표시한다.
- Unity Console에 누락 스크립트, NullReferenceException, 빌드 씬 오류가 없다.
